# Acceptance checklist for the future implementation

These boxes begin unchecked. They are requirements, not claimed test passes. Record evidence and actual limits in the final QA report.

## Product and navigation
- [ ] Root retains two clear buyer/seller choices.
- [ ] Buyer opens marketplace and Seller opens prepared workspace.
- [ ] Role switching is visible and preserves unrelated state.
- [ ] Four available products and two coming soon follow the approved mix.
- [ ] Every product card opens the correct item.
- [ ] Direct routes, refresh, back navigation and query state work.
- [ ] No mandatory signup, personal details or permission prompts.

## Marketplace
- [ ] Search, categories, filters and sorting change results correctly.
- [ ] Empty results and reset actions are useful.
- [ ] Each active item has correct product, seller, photo and model records.
- [ ] Coming-soon items are unavailable to cart/review.
- [ ] Sample sellers and empty reviews avoid fabricated reputation.
- [ ] Saving and collections support all active products.
- [ ] One-off quantity, availability and repeated cart actions are consistent.
- [ ] Seller-group delivery assumptions and totals are explicit and correct.
- [ ] Checkout is editable review without a real transaction claim.

## 3D and evidence
- [ ] Each active item has its own genuine model.
- [ ] Models, images, bounds and displayed dimensions agree.
- [ ] Sora articulation and condition evidence remain coherent.
- [ ] Controls reflect each product's actual capabilities.
- [ ] Product viewer/gallery state is isolated.
- [ ] Room/size results retain correct measurement context and limitations.
- [ ] Reproducible generation source is supplied for new assets.
- [ ] No reconstruction, AI damage grading or physical-fit guarantee is invented.

## Prepared experiences
- [ ] Sora alone has capture.
- [ ] Mobile capture fills usable viewport and has reachable controls and exit.
- [ ] Next changes area/view/instruction and shutter selects corresponding frame.
- [ ] Review is reachable without completing repetitive steps.
- [ ] Prepared reset does not erase unrelated data.
- [ ] Photo search visibly starts from a predetermined chair example.
- [ ] Matching reasons, local result mapping and independent size filtering work.
- [ ] Photo-search empty state and recovery work.
- [ ] Camera/file APIs and permission attempts are absent from served journeys.

## Mobile performance and accessibility
- [ ] Phone, tablet and desktop screenshots inspected.
- [ ] Touch scrolling, view presets, zoom alternatives and reachability verified.
- [ ] Safe areas, short heights, dialogs and keyboard focus checked.
- [ ] Text/control contrast, meaningful labels for inputs and sliders, and accessible inline errors verified.
- [ ] Dialog focus containment and return verified, with inactive background content appropriately managed.
- [ ] Navigation updates page title and focus sensibly without hiding the focused element.
- [ ] Reduced motion affects actual engine transitions.
- [ ] Role/catalogue does not fetch GLBs or mount catalogue renderers.
- [ ] Adaptive loading and customer override verified.
- [ ] Lightweight profile checked in inspection and full-screen capture.
- [ ] Idle, offscreen and background work stops appropriately.
- [ ] Renderer/resource counts remain bounded across repeated switching.
- [ ] Constrained network/CPU conditions and cold/warm loads documented.
- [ ] Failed asset/WebGL/context conditions preserve a useful experience.
- [ ] Metrics and claimed budgets have actual evidence.
- [ ] Emulation, software WebGL and physical-device results are distinguished.

## Brand and artifacts
- [ ] Original code-authored logo and editable source supplied.
- [ ] Small-size, monochrome, reversed and header applications inspected.
- [ ] Website and guidelines use the same final tokens/assets.
- [ ] Guidelines are editable PPTX, not flattened full-slide screenshots.
- [ ] PDF exported from final PPTX and all pages inspected.
- [ ] No clipping, overlap, missing fonts or drafting residue.
- [ ] Licences, source attribution and original/derived provenance retained.
- [ ] Final application source and fresh dist/ agree.
- [ ] Production output verified and Vercel ZIP complete.
- [ ] Private references, prompts, credentials and caches excluded from deployed output.

## Final review
- [ ] Demanding review and revision completed with truthful evidence.
- [ ] Independent review claimed only if actually performed.
- [ ] No known critical or major unmet requirement concealed.
- [ ] Remaining material gaps disclosed outside public deliverables.
